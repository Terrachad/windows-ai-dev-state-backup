# Support

Start with [usage](docs/usage.md), [troubleshooting](docs/troubleshooting.md) and [recovery](docs/recovery.md).

For a bug report, include the release version, Windows edition/build, Python version, command, a short redacted error and a synthetic reproduction. State whether you were backing up, verifying, rehearsing or applying a restore. Do not upload archives or raw session/configuration files.

Questions about workflow belong in Discussions when enabled. Reproducible defects and supported-layout requests belong in the relevant issue forms. Security-sensitive failures should use private reporting as described in SECURITY.md.

This is community-maintained software, without a guaranteed support response time. A failed restore should not be retried blindly: stop applications, preserve every copy and follow the recovery guide first.
